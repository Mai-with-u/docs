# 文件功能

文件功能让麦麦收发聊天附件：别人在群里发的文件、你在网页里上传的文件、麦麦自己生成的文本，都能保存下来按需读取。它运行在主程序里，不依赖 WebUI、沙盒电脑或外接 Agent。

**能做什么**：保存与下载接入后收到的附件，读取常见文本文件，在网页聊天里发文件。**不能做什么**：不遍历已有的群文件目录；Office、PDF 这类二进制文件可以存储和收发，但不解析内容。

## 开启

文件功能默认关闭。在 WebUI「能力 → 文件功能」打开，或者直接改配置：

::: code-group

```toml [bot_config.toml ~vscode-icons:file-type-toml~]
[capabilities]
files = true    # 总开关：附件登记、模型文件工具、插件文件接口、WebUI 文件入口
```

:::

这个开关热重载生效，统一控制上面四个入口；关闭后拒绝新的文件操作，**已有原件不会被删除**，缓存清理策略照常运行。WebUI 开关和 HTTP 服务各自独立，关掉 WebUI 不影响 QQ 收发文件。

## 三个入口

**QQ** — 统一 QQ 连接器的 NapCat、SnowLuma 画像会把文件消息和群上传通知作为结构化附件交给主程序。适配器原有的通知开关和聊天过滤照常生效；接收群上传通知需要打开对应通知设置。

**WebUI** — 聊天输入框的回形针先上传附件再随消息发送；「文件」页面按聊天实际名称筛选，提供上传、下载、文本阅读和管理。移除草稿里的附件不删原件，原件要到文件管理页手动删除。

**模型工具** — 麦麦可调用 `files_list`、`files_download`、`files_read_text`、`files_create_text`、`files_send`，但只在可信执行上下文里可用：插件不能靠提交 `session_id` 选择聊天，定时任务和普通 API 调用也没有聊天授权。文件内容是外部数据，不会被当作指令执行。

管理员可以在文件管理页选目标聊天并确认后跨聊天发送；普通工具和插件 SDK 都不提供跨聊天授权。

## 存储与配额

::: code-group

```toml [bot_config.toml ~vscode-icons:file-type-toml~]
[files]
max_file_mib = 50              # 单文件上限
max_storage_gib = 10           # 实例总配额，含下载、原件与上传预留
max_text_mib = 8               # 文本解析上限；更大的文件仍可收发下载
cache_days = 30                # 平台下载缓存保留天数
max_concurrent_transfers = 4   # 同时传输数量
transfer_timeout = 120         # 单次传输超时秒数
transfer_base_url = ""         # 客户端可访问的后端地址；留空用 [http]
trusted_download_origins = []  # 允许下载的内网适配器来源
```

:::

平台附件先登记元数据，等你明确要求下载或读取时才去取内容；缓存按最后访问时间保留 30 天后清理。本地上传和生成的内容属于原件，一直保留到手动删除。达到额度会拒绝新增，不会自动删原件。

传输按单文件最大容量预留空间，所以剩余空间不足一个单文件额度时也会拒绝开始。并发上限调低后，正在进行的读取允许结束，新操作按新上限准入。

文件放在实例的 `data/files` 目录，磁盘名由主程序生成，与上传文件名无关；首次写入时计算 SHA-256。文本解析支持 UTF-8、带 BOM 的 UTF-16，以及显式指定 GB18030，不执行文档里的脚本或宏。

## 同机与异机部署

文件字节走公共后端的 `/api/files/transfers/...`，HTTP 服务随主程序启动。`webui.enabled = false` 只关闭管理页面和管理接口，QQ 和插件的收发不受影响。

`transfer_base_url` 留空时使用 `[http]` 里 `host` / `port` 指定的本机地址（默认回环、8001 端口）；`7999` 只是前端开发端口。QQ 客户端在另一台机器上时，必须填客户端能访问的地址，并配好后端监听、反向代理和网络放行；跨机器建议用 HTTPS。

监听配置属于 `[http]`，改地址或端口后要重启。环境变量 `HTTP_HOST` 可以追加监听地址。对外只提供文件传输时，反向代理只转发 `/api/files/` 即可。

平台下载只允许 HTTP(S)，拒绝 URL 内嵌凭证，实际 DNS 连接和每一跳重定向都会检查目的地址，默认禁止内网、回环、保留和组播地址。如果平台给的是私网下载地址，管理员要在 `trusted_download_origins` 里写精确来源，如 `http://192.168.1.20:3000`；不接受通配符，也不要填用户能控制的服务。

令牌只授权一个操作和一个文件，默认五分钟失效，服务重启后全部失效。不要把传输 URL 当成永久文件链接或写进公开日志；需要长期引用时用 `file_ref`，后端每次都会重新检查聊天授权。

## 验证与排错

**验证** — 打开开关后在网页聊天里用回形针上传一个文本文件，能在「文件」页看到并按聊天筛选；让麦麦列出当前聊天文件，应能看到这一条。

**页面提示文件功能已关闭** — 总开关在 `[capabilities].files`，不在 `[files]` 段；保存后确认日志出现重载成功。

**发送失败或一直未下载** — 平台缓存需要主动请求才下载，先点下载或阅读；检查 `transfer_base_url` 是否是客户端能访问的地址，反向代理是否转发了 `/api/files/`。

**拒绝内网下载地址** — 平台给的是内网地址时，把精确的 `http(s)://主机:端口` 写进 `trusted_download_origins`，不要用通配符。

**空间不足但看起来还有余量** — 传输会按单文件上限预留空间，剩余额度不足一个单文件上限时也会拒绝开始；调低 `max_file_mib` 或清理原件后再试。

**删不掉文件** — 传输令牌有效期内或下载响应进行中，清理与删除会被拒绝，以固定被读取的内容；等传输结束后再删。
