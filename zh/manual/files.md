# 文件功能

文件功能让麦麦收发聊天附件、保存文件并阅读常见文本文件。运行时不需要 WebUI，也不依赖外接 Agent；`webui.enabled = false` 只关闭管理页面，不影响收发。

当前支持接入后收到的聊天附件、本地上传和生成文本，不遍历已有群文件目录。Office、PDF 等二进制文件可以存储和收发，但不解析内容。

## 开启

在 WebUI「能力 → 文件功能」打开，或在 `bot_config.toml` 中设置 `capabilities.files = true`。开关热重载生效，统一控制附件登记、模型工具、插件 SDK 和文件 HTTP 入口。

关闭后拒绝新的文件操作，不删除已有原件，原有缓存清理策略继续生效。HTTP 服务器与 WebUI 开关仍各自独立。

## 各入口能做什么

::: fields
- **QQ** — OneBot 适配器把收到的文件消息与群上传通知作为结构化附件交给宿主。接收群上传通知需要开启对应的通知设置。
- **WebUI** — 聊天输入框的回形针先上传附件再随消息发送；「文件」页面按聊天实际名称筛选，提供上传、下载、文本阅读和管理。移除草稿附件不删除原件，可在文件管理里手动删除。
- **模型** — `files_list`、`files_download`、`files_read_text`、`files_create_text`、`files_send` 只接受当前可信执行上下文。文件内容属于外部数据，不能当作工具指令执行。
- **管理员** — 在文件管理页选择目标聊天并确认后才能跨聊天发送。普通工具和插件 SDK 不提供跨聊天授权接口。
:::

## 存储与配额

`files` 配置节由配置系统生成，不用手动建目录或改数据库：

::: code-group

```toml [bot_config.toml ~vscode-icons:file-type-toml~]
[files]
max_file_mib = 50                 # 单文件上限（MiB），按实际接收字节数校验
max_storage_gib = 10              # 实例文件存储配额（GiB），含下载、原件与正在上传的预留
max_text_mib = 8                  # 文本解析上限（MiB），最大可设 50；更大的文件仍可收发与下载
cache_days = 30                   # 平台下载缓存最后访问后保留天数；本地上传和生成的原件不会自动删除
max_concurrent_transfers = 4      # 同时上传下载数量上限，1～32
transfer_timeout = 120            # 单次传输超时秒数，10～3600
trusted_download_origins = []     # 允许下载的内网适配器来源，精确到 http(s)://主机:端口
```

:::

平台附件先登记元数据，明确请求下载或读取时才获取内容；缓存按 `cache_days` 在最后访问后清理。本地上传和生成的内容属于原件，保留到手动删除。达到配额会拒绝新增，不自动删除原件。传输按单文件最大容量预留，所以剩余空间不足一个单文件额度时也会拒绝开始传输。

文件放在实例 `data/files` 中，磁盘名称由宿主生成，与上传文件名无关；首次写入计算 SHA-256。文本读取按字符分页，每次最多 32000 字符，支持 UTF-8、带 BOM 的 UTF-16 以及显式指定的 GB18030，不执行文档脚本或宏。

## 同机与异机部署

文件字节通过宿主统一地址 `/api/files/bots/<bot_id>/transfers/<token>` 传输。宿主默认监听 `127.0.0.1` 与 `::1` 的 8001 端口，所有 Bot 共用这一个对外地址；7999 只是前端开发服务端口。

地址写在宿主配置 `host/config.toml` 的 `[webui]` 段：`hosts`、`port` 决定监听，`public_base_url` 决定生成文件链接时用的外部地址，改完需要重启宿主。QQ 客户端部署在另一台机器时，把 `public_base_url` 填成客户端能访问的地址，并放开监听、配置反向代理；跨机器建议使用 HTTPS。`HTTP_HOST` 环境变量可以追加监听地址，Docker 部署靠它监听容器网卡。

对外只提供文件传输时，反向代理可以只转发 `/api/files/`。

## 下载白名单

平台下载仅允许 HTTP(S)，拒绝 URL 内嵌凭证，实际 DNS 连接及每一跳重定向都会检查目的地址，默认禁止内网、回环、保留和组播地址。

平台提供私网下载地址时，管理员要在 `files.trusted_download_origins` 中列出精确来源，例如 `http://192.168.1.20:3000`；不允许通配符或任意用户指定下载地址。

## 令牌与引用

令牌只授权一个操作和一个文件，默认五分钟失效，服务重启后全部失效。不要把传输 URL 当作永久文件链接或写进公开日志。

需要长期引用时用 `file_ref`，后端每次检查聊天授权。发送凭证有效期内以及下载响应进行期间，清理和删除会被拒绝，以固定被读取的内容。

## 插件接入

SDK 2.17.0 的 `ctx.files` 在宿主派发的工具调用期间可用。插件在 manifest 里声明对应的 `files.*` 精确能力名称；宿主在调用开始签发聊天权限，结束或取消时撤销，SDK 不能靠提交 `session_id` 选择聊天。定时任务、普通 API 和无聊天上下文的调用会拒绝访问。

插件在本地读取上传路径并通过流式 HTTP 上传；下载独占创建本地目标文件并校验大小和哈希。宿主不接受插件在 RPC 中传入的任意本地路径、任意下载 URL 或大段 Base64。开发期间可用 `MAIBOT_PLUGIN_SDK_PATH` 指向本地 SDK 仓库。

发送返回 `sent` 或 `unknown`。`unknown` 表示没有取得确定的发送成功回执，平台仍可能稍后投递，必须核对聊天，不要自动重发。

## 验证与排错

**验证**：在 WebUI 聊天输入框点回形针上传一个文本文件并随消息发送，然后到「文件」页面按该聊天筛选，能看到文件、能下载、能在线阅读。

- **回形针不出现** — 确认「能力 → 文件功能」已打开，`capabilities.files` 为 `true`。
- **上传被拒绝** — 看单文件大小是否超过 `max_file_mib`，以及实例存储是否接近 `max_storage_gib`；达到配额不会自动删旧文件。
- **异机 QQ 收不到文件** — 检查 `host/config.toml` 的 `webui.public_base_url` 是否填了客户端能访问的地址，`webui.hosts` 是否对外开放，反向代理是否转发了 `/api/files/`。
- **内网下载被拒** — 把精确来源加进 `files.trusted_download_origins`，不要写通配符。
- **链接过期** — 传输令牌默认五分钟失效，长期引用改用 `file_ref`。
