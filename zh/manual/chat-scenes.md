# 聊天场景

麦麦在群聊和私聊里是两套不同的行为：群聊按批次决定要不要查看，私聊盯住一个人的节奏。这个页面说明这些差异怎么调。

## 群聊查看频率

群聊里每批消息要不要进入 Planner，由「群聊查看频率」决定，取值 0～1，默认 `1`。它是每批消息的基础概率，不代表实际回复比例——查看之后还有说不说、说几句的判断。`0` 不主动查看，`1` 按满概率查看；实际能连着查看多少批，由下面的衰减决定。

查看一次之后，内部频率从该值开始，每次有效 Planner 运行减 1/16；归零前查看概率始终为 1，衰减期内不重复激活。归零后进入恢复期，在 16 次判定中恢复到基础概率；恢复期间再次激活会重新开始衰减。频率变化不会终止正在运行的 Planner 循环。因此基础概率决定的是激活后能连续查看多少轮：`1` 大约 16 轮，`0.5` 大约 8 轮。

麦麦还会按当前和上一轮上下文里外部消息的平均接收间隔预测下一条消息，到期仍没有消息时也做一次概率判定。这个值只作用于群聊，私聊另有一套暂停开关。

## 动态查看规则组

按场景给不同群设不同的查看概率。规则组可以新建、复制和切换，每组里保存若干条规则；只有当前规则组内启用的规则参与匹配。

::: fields
- **`enabled`** — 关闭后保留该规则，但不参与匹配。
- **`platform`** — 生效平台；留空表示不限定平台，`*` 表示任意平台。
- **`item_id`** — 群号或用户 ID；留空表示不限定聊天，`*` 表示任意聊天。
- **`rule_type`** — `group` 或 `private`。
- **`time`** — 生效时间段；留空为兜底，`*` 为全天，也可填 `23:00-02:00`。
- **`value`** — 该规则下的外部查看概率，取值 0 到 1；0 不主动查看。
:::

群聊规则必须指定平台或群聊 ID，写成通配会在配置校验时直接报错；所有群的默认概率用「群聊查看频率」调。

规则组名称不能为空、不能有首尾空白，也不能重名；启用的规则组必须存在，否则配置校验会直接报错。

## 消息防抖

防抖决定一批消息等多久再送去判断。群聊和私聊各有独立档位，默认都是「自然」：

::: fields
- **关闭** — 新消息不等待，直接进入判断。
- **快速** — 安静 1 秒、活跃 3 秒；同人续发 1 秒，群聊换人 0.5 秒。
- **自然** — 默认。群聊安静 2.5 秒、活跃 6 秒，同人续发 2.5 秒、换人 1 秒；私聊安静 2 秒、活跃 5 秒，续发 2 秒。
- **沉稳** — 群聊安静 5 秒、活跃 9 秒，同人续发 5 秒、换人 3 秒；私聊安静 4 秒、活跃 7 秒，续发 4 秒。
:::

新批次按上一条有效消息的间隔选择初始等待：超过 30 秒没有有效消息按安静开批，否则按活跃开批。三档共用的规则：裸图开启新批次时至少等 4 秒，后续消息仍按续发规则重算；批次内纯表情包不能延长等待，但可以提前结束。整批从第一条实际收到起算，群聊在快速、自然、沉稳下分别最多等 8、10、12 秒，被 @ 或提及时分别最多等 1、2、3.5 秒，连续提及取最早上限；私聊整批最多等 8 秒，被提及时直接结束等待。上限优先于其他等待规则。

换档从下一条有效消息起生效，不重置批次或提及上限；选择关闭会结束正在进行的等待。这里的等待时间不包含模型生成和发送耗时。

## 快速反应

「快速反应模式」默认关闭，仅群聊生效：强制 Planner 使用流式请求，思考或输出期间收到新消息时立即打断并带上新消息重新请求。私聊和 wait 唤醒不受这个开关控制。

被打断的思考与输出保留在历史里，可以在麦麦观察中查看。

## 私聊暂停

开启「暂停私聊回复」后，所有私聊只接收消息并维护历史，不进入思考。单个私聊可以通过暂停规则覆盖全局设置：按平台和用户 ID 指定，开关在聊天流设置里切换或恢复跟随全局。

## 私聊 Planner 模板

普通私聊使用 `maisaka_chat_private`，开启被动回复时使用 `maisaka_chat_private_passive`。两套模板围绕当前用户的消息、未完成请求和连续对话做决策，输出协议分别沿用 `reply` 工具和自然语言回复指导；私聊注意事项、记忆查询规则、注意力漂移与工具权限继续按私聊场景注入。

群聊和未绑定会话使用 `maisaka_chat` / `maisaka_chat_passive`，Focus 使用 `maisaka_chat_focus`，同属一个 Focus 组的私聊也遵守 Focus 的统一协议。中英日三套私聊模板都可以在 Prompt 管理页单独编辑；已有的通用 Planner 自定义模板不会自动套用到新的私聊模板上。

## Focus

Focus 让同组聊天共享一个持续思考的 Planner：所有成员的消息共同进入上下文，工具通过 `session_id` 指定处理目标。

::: fields
- **`focus_mode`** — 总开关，默认关闭。
- **`focus_on_private`** — Focus 是否也作用于私聊，默认关闭。
- **`focus_groups`** — Focus 组的成员列表。同组聊天共享 Planner 与完整上下文，不同组独立运行；未匹配任何组的聊天使用原本模式。留空时所有聊天都用原本模式。
- **`focus_chat_whitelist`** — 在已匹配组的聊天中进一步限制范围；留空表示不额外限制，仍须属于某个组。
:::

Focus 仍然按各自场景的规则检查准入。连续等待后，提示麦麦延长等待或主动结束对话。

## 聊天单次日程

群聊、私聊和 Focus 共用同一个 `schedule` 工具：麦麦可以给自己定一个到点执行的单次任务，到期后回到原聊天继续做。

::: code-group

```json [新增日程 ~vscode-icons:file-type-json~]
{"action": "add", "text": "提醒大家提交作业", "delay_seconds": 600}
```

:::

也可以用 `due_at` 指定具体时间（ISO 8601，建议带时区），它和 `delay_seconds` 不能同时填。工具支持 `list`、`update`、`cancel`、`complete`，改动之前先 `list` 查出真实的 `todo_id`。Focus 里要额外填本组的真实 `session_id`，其他模式自动绑定当前聊天。

日程由主程序持久化并每秒检查，不依赖桌宠是否启动。到期时向原聊天投递一个内部任务并唤醒 Planner，正在定时等待的 Focus 组也会被唤醒；Planner 结合最新上下文执行，完成后归档。日程只会回到原聊天，不会投给其他群，也不会把跨群事项塞进主人聊天的常驻待办。创建日程不暂停当前轮次，也不代表到期消息已经发出。

桌宠面板、主人 `desktop_pet_todo` 和 `schedule` 共用同一份事项文件与附件：桌宠是管理入口，主程序是唯一写入方。重启后会补投递尚未确认的到期任务；状态 `triggered` 只表示已投递，`failed` 会保存错误，重新安排到未来时间才会再试。进程如果在「投递成功」和「写入回执」之间退出，可能重复投递，所以不保证严格只执行一次。

取消会保留记录，完成会归档；`list(include_completed=true)` 能查到已完成和已取消的历史。

## 引用频率

群聊和私聊的引用（回复时带上原消息）各有独立档位：不引用、偶尔引用、经常引用，默认偶尔引用。经常引用的概率是偶尔引用的两倍。

群聊按固定规律随机决定；私聊结合用户连发条数、发言间隔和回复目标位置随机决定。

## 验证与排错

**验证**：在一个群里把「群聊查看频率」调到 `0.2` 保存，观察半小时，麦麦进入思考的次数应明显减少；调回 `1` 后查看明显变多，但连续查看十几轮后会自己停下来歇一段。

- **规则不生效** — 确认规则所在的规则组就是当前启用的组，且规则本身没有被关闭。
- **配置保存时报错** — 检查规则组名是否为空、有无首尾空白或重名；群聊规则是否漏了平台或群号。
- **麦麦太吵或太安静** — 先调「群聊查看频率」，再考虑用动态查看规则组按群细分；防抖档位影响的是等待时间，不改变查看概率。
- **上下文裁得太早** — 检查是否打开了 Token 上限，阈值过低会在消息还不多时裁掉旧历史；也可以把「群聊上下文」或「私聊上下文」调大。
- **私聊完全不回** — 检查「暂停私聊回复」是否打开，以及是否有命中该用户的暂停规则。
