# 查看和管理记忆

长期记忆存在本地数据目录里，WebUI 的「长期记忆」页（`/resource/knowledge-base`）把查询、写入、修正、抹除和调优都集中在一处。记忆系统本身的参数见 [A_Memorix 配置](../configuration/amemorix-config.md)。

![长期记忆](/images/webui/knowledge-base.webp)

## 六个标签

标签分为两排：

::: fields
- **记忆查询** — 搜索文字记录、关联内容和人物画像，内部再分「文字记录」与「人物画像」两个视图。
- **图片记忆** — 图片资产、图片认知、视觉相似检索与历史回填。
- **记忆流** — 按聊天流核对记忆的新增、更新与删除。
- **导入导出** — 创建导入任务、导入导出记忆包、手动新增事实。
- **记忆检修** — 内容修正、状态维护、检索调优、情景记忆、画像维护、纠错历史。
- **记忆抹除** — 按来源批量抹除，并回滚某次抹除。
:::

标签行右侧的「更多操作」里有「查看记忆状态」和「打开图谱」。向量库与当前 embedding 模型指纹不一致时，这一行会多出一个红色的「重建向量」。

## 搜索记忆

「记忆查询 → 文字记录」的搜索框同时匹配内容、名称、关系、事实、情节和 ID。旁边的「记录类型」把结果限定在段落、实体、关系、事实或情景记忆，开关「显示停用」会把已失效的记录一并列出。

结果支持多选后「修正所选」，批量修正覆盖段落和关系；事实逐条编辑，实体在图谱里改。

「人物画像」子视图按平台加用户账号精确定位，或按名称、群名片、person_id 模糊查找。

![记忆查询](/images/webui/knowledge-query.webp)

## 知识图谱

「打开图谱」展示实体、关系及其证据链，可按段落 hash 直接定位到某个节点。图谱只能查看和删除错误节点、关系或证据段落，不能手工新建；修正内容走「记忆检修 → 内容修正」。

![长期记忆图谱](/images/webui/knowledge-graph.webp)

## 图片记忆

图片记忆需要先在 `model_config.toml` 的 `[model_task_config.image_embedding]` 里配置一个支持图片输入到向量的模型。没配时图片和认知照常保存，只是检索不可用。相关参数见 [A_Memorix 配置 → 图片记忆](../configuration/amemorix-config.md#图片记忆)。

选中一张已入库的图片后，可以在「相似图片」里按相似度阈值检索，结果区分「同一图片」与「相似图片」，并展开命中图片所在聊天、认知和关联记忆。

「查看历史图片回填」打开「图片记忆高级维护」对话框，里面的「图片维护」面板有四个折叠区：

::: fields
- **入库失败任务** — 首轮入库失败会自动重试，达到上限后保留错误；修好原因可以整批重新排队。
- **历史图片回填** — 先预览扫描历史消息并分类（可恢复、已回填、文件缺失、聊天流缺失、来源缺失、图片不支持或损坏、写入失败），确认后再执行。执行时会重新校验，并忽略预览之后新到的消息。
- **索引状态与任务诊断** — 处理索引队列，查看已入队任务与失败原因。
- **模型指纹与启动恢复记录** — 当前图片向量世代与启动时的恢复情况。
:::

回填里出现「文件缺失」是历史图片二进制已被清理，不影响新图片入库；连续显示「等待构建」时先确认图片嵌入模型可用。

## 记忆流

「记忆流」按聊天流和事件类型列出记忆变动：段落、记忆片、人物画像、反馈纠错、删除恢复、维护操作，可选最近 24 小时、7 天或 30 天。

![审计时间线](/images/webui/knowledge-timeline.webp)

## 导入资料

「导入导出 → 导入任务」把外部资料喂给记忆系统，右上角 `⋮` 切换三种任务类型：

::: fields
- **资料导入** — 上传文本、文件或文件夹。
- **LPMM OpenIE** — 读取 LPMM 数据并抽取关系。
- **LPMM 转换** — 把 LPMM 数据转换到目标目录。
:::

入库前先选资料类别，它决定切块与抽取方式：叙事资料按场景切分后滑动窗口（默认 1600 字窗口、400 字重叠），事实资料按结构切块（默认 1200 字，不拆列表与定义），语录与短句整段保留不做关系抽取，聊天记录按消息边界切块。

「导入参数」里的公共参数与高级参数决定新建任务怎么切块和抽取，不写回配置文件；上限与并发见 [A_Memorix 配置 → 导入中心](../configuration/amemorix-config.md#导入中心)。

![导入记忆](/images/webui/knowledge-import.webp)

## 记忆包

「记忆包导入导出」把一台 MaiBot 的记忆搬到另一台，或做成可分享的 `.amembundle` 文件。

导出时选内容级别和范围：

::: fields
- **知识** — 段落、实体、关系及其向量，等价于一份 LPMM 同语义知识包。
- **完整** — 在知识之外加上人物画像、情景记忆、事实账本、外部引用和生命周期状态，适合整机迁移或完整备份。
- **导出范围** — 全部记忆、指定聊天流、指定来源、指定导入任务、已安装知识包，或单独挑选图片。
- **携带兼容向量** — 打包向量以加快相同 embedding 配置下的安装；不带时安装侧现场补建。
:::

安装前先检查文件：页面会给出体积、图片数、缺失资源数和向量兼容性结论。安装范围可选「所有聊天可用」或「指定聊天流」，安装方式选「合并安装」或「空库恢复」（后者用于整库搬移）。

包内成员包括 `manifest.json`、`knowledge.json`、可选的 `state.json`、段落与关系向量，以及图片记忆的 `images.json`、`images/assets/`（原始图片）和可选的 `vectors/images.npz`（图片向量）。限额是单包 4096 个成员、单个成员解压后 256 MiB、解压总计 1 GiB；不带图片扩展的记忆包同样可以安装，只是不含图片记忆内容。

安装只搬运已有内容并补齐缺失向量，不重新做抽取。图片向量与本地模型指纹一致时直接复用；不一致、缺失或模型暂不可用时仍完成内容安装，图片检索状态显示为待构建，之后按本地模型补建。卸载记忆包会清掉包内独占资源，仍被其他聊天流或其他记忆包引用的共享图片保留。

## 修正记忆

「记忆检修 → 内容修正」用一句自然语言描述要改什么，选修正范围（可以只针对某个人物画像），系统给出变更计划与级联影响预览，确认后执行；执行过的计划可在「修正计划」里回滚。「纠错历史」记录检索纠错与回滚。

「记忆检修 → 画像维护」维护单个人物的支撑证据、别名与字段覆写，入口需要先在「记忆查询 → 人物画像」里选中一个人物。

「记忆检修 → 情景记忆」管理 Episode 的生成状态，可按待重建、运行中、已完成、失败来源筛选。

![纠错历史](/images/webui/knowledge-feedback.webp)

## 抹除与恢复

「记忆抹除」分两块：

::: fields
- **按来源抹除** — 勾选来源后预览删除，能看到会波及的实体、关系、段落数量，确认后进入回收站。
- **删除记录** — 按模式、状态、关键词查历史操作，执行过的删除可以整次恢复。
:::

被删的关系留在「记忆检修 → 状态维护 → 记忆回收站」里，可以按行单独恢复。删除不会立即物理清除，也不影响仍被别处引用的共享数据。

![删除记忆](/images/webui/knowledge-delete.webp)

## 人物画像

人物画像记录性格、兴趣与聊天习惯。在「记忆查询 → 人物画像」里查看，或打开 `/resource/person`（人物信息管理页）集中管理：按名称搜索，按认识状态和平台筛选，编辑人物名称、昵称、名称设定原因与个人印象，也可以勾选后批量删除。

![人物信息管理](/images/webui/person.webp)

## 检索调优

记不住东西时跑一次调优：「记忆检修 → 检索调优」从真实记忆里采样问题，按优化目标（优先准确率、准确率与召回平衡、优先召回率）和强度（快速、标准、深入）评估候选检索参数，给出综合评分与独立样本验证结论。

调优参数只影响下一次任务，一般保持默认。结果标为「推荐」时才建议应用：应用只热合进当前运行时，勾选「同时保存为默认设置」才会写回配置。

![检索调优](/images/webui/knowledge-tuning.webp)

## 状态维护

「记忆检修 → 状态维护」处理单条关系的生命周期：

::: fields
- **维护操作** — 对关系 hash 或查询文本命中的关系执行强化、冻结、保护、恢复；保护可以按时长，留空表示永久。
- **记忆回收站** — 列出已删除的关系，支持按行恢复。
:::

被保护或 pin 的关系不参与记忆演化的衰减和裁剪。

![状态维护](/images/webui/knowledge-maintenance.webp)

## 验证与排错

**验证**：导入一段文本，任务状态变成「已完成」后，在「记忆查询」里能搜到相关内容。

- **导入任务一直排队或失败** — 确认已配置可用的模型服务商（导入要做抽取和向量化），再看任务详情里的失败原因。
- **搜不到刚导入的内容** — 确认任务状态是「已完成」，再检查向量是否构建完成；顶部出现「重建向量」时先重建。
- **图片检索一直显示等待构建** — 确认 `[model_task_config.image_embedding]` 配了支持图片输入的嵌入模型；模型不可用时页面会显示对应错误。
- **回填里大量「文件缺失」** — 历史图片二进制已被清理，属正常现象，不影响新图片入库。
- **记忆会存多久** — 默认长期保留。记忆演化只让「关系」随时间衰减，低强度的关系被冻结、归档后进回收站，默认约 3.3 天从 1.0 衰减到 0.1 以下。
- **记忆会不会外泄** — 记忆数据保存在本地目录；生成摘要、画像、纠错或向量时会调用你配置的模型服务，数据边界取决于你的部署方式和模型提供商。
