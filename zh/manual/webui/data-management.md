# 数据管理

数据管理把配置、数据、插件和日志打包成 zip 下载，或从 zip 还原。入口在侧栏 **高级工具 → 数据管理**。

## 导出

选择范围后开始导出。导出在后台运行，同一时间只能运行一个导出任务；压缩包临时保存在系统临时目录，过期后自动清理，每次下载开始和完成时把保留期限重置为 24 小时。

压缩包名为 `maibot-data-<导出时间>.zip`，例如 `maibot-data-20260709-123456.zip`。

## 包结构

包顶层固定包含 `manifest.json`，其余是按勾选范围打包的 `config/`、`data/`（以及可选的 `plugins/`、`logs/`）目录，包内路径与实例目录内的相对路径一致。

::: code-group

```json [manifest.json ~vscode-icons:file-type-json~]
{
  "format": "maibot-data-archive",
  "format_version": 1,
  "created_at": "2026-07-09T12:34:56.789012+00:00",
  "maibot_version": "1.3.2",
  "included": ["config", "data"],
  "parts": {
    "config": { "file_count": 12, "total_bytes": 1048576 },
    "data": { "file_count": 3456, "total_bytes": 209715200 }
  }
}
```

:::

导入时由后端校验这份元信息。

## 多实例下的行为

数据传输由宿主提供，目标 Bot 停止时仍可使用。执行前宿主会停止目标进程并持有实例进程锁，完成后按原期望状态恢复；上传、压缩和磁盘事务不占用 WebUI 事件循环。

::: fields
- **任务隔离** — 任务记录、下载文件和临时目录按 Bot ID 隔离，切换 Bot 不会沿用前一个 Bot 的任务。
- **导入范围** — 只覆盖所选分类中包内提供的文件，不删除目标实例的其他普通文件。
- **数据库替换** — 替换 SQLite 数据库时清除目标旧库的 WAL、SHM 和 journal，避免旧事务污染新库。
- **拒绝项** — 路径越界、符号链接及重复路径会被拒绝。
:::

导入前会把被覆盖的文件备份到目标 Bot 的 `temp/data-import/<事务 ID>/backup/`，同目录的 `backup-manifest.json` 记录原路径；失败按事务日志回滚，进程中断后下次打开工作区先恢复未完成事务。

导出的配置包含当前 Bot 使用的模型、供应商和联网服务定义。导入旧配置时，定义合入公共模型目录：同名但不同的定义保留原公共项，为导入项另取名称并修改当前 Bot 的任务引用，其他 Bot 的引用不变。旧包中的网络地址、缓存与日志保留策略不会覆盖现有宿主公共配置。

配置历史备份不进入导出包，也不从旧包恢复。

## 备份建议

导入会覆盖现有文件。导入前先备份当前数据，可以用本页再导出一份留底，并确认 `manifest.json` 里记录的版本与当前一致。导入完成后重启 Bot 再验证运行状态。

不需要迁移时，直接停止实例并复制整个实例目录也是可行的备份方式。

## 验证与排错

**验证**：导出一次完整数据包，确认下载的 zip 里有 `manifest.json`；再导入该包，导入完成后重启 Bot，聊天与配置应恢复原状。

- **导出按钮没反应** — 同一时间只能运行一个导出任务，先等当前任务结束。
- **下载链接失效** — 保留期限在每次下载开始和完成时重置为 24 小时，过期后重新导出。
- **导入后少了文件** — 导入只覆盖包内提供的文件，不删除其他文件；缺的内容说明导出时没有勾选对应范围。
- **导入被拒绝** — 检查包内是否存在路径越界、符号链接或重复路径，这三类会被直接拒绝。
- **导入后配置没变** — 旧包的公共网络与保留策略不会覆盖宿主配置，这是预期行为；模型与联网服务会合入公共模型目录。
