# 聊天流迁移

把一个聊天流的历史、配置和学习成果复制合并到另一个聊天流，用来在换群、换号或合并同类会话后保留上下文。入口在 WebUI「数据管理 → 聊天迁移」。

## 能做什么

选择已存在的来源和目标聊天流，预览数据，逐条处理冲突后执行。平台、账号、群聊与私聊的组合不受限制，来源和目标可以是不同类型的聊天流。

迁移是复制合并：来源不会被删除，也不会改成跳转到目标。目标保持自己的收发身份，历史消息保留原平台、发送者和消息内容。

迁移期间只暂停双方的入站处理、聊天实例和对应记忆任务，其他聊天流照常运行。等待中的入站消息在暂停解除后继续处理，主动暂停的状态不因迁移改变。

## 迁移范围

会迁移的数据：

::: fields
- **聊天记录** — 消息、工具记录、用量、观察与回复评估记录、附件绑定。
- **学习成果** — 表达、黑话、学习命令、词频。
- **统计与关系** — 聊天用量汇总和[相通组](./sharing-groups.md)成员关系。
- **聊天配置** — 精确匹配来源平台、对象和聊天类型的规则。
- **长期记忆** — 目标聊天范围内的段落归属、事实与证据、情节、图片引用及摘要检查点。
:::

不迁移的数据：

- 附件内容仍是实例内已有的文件，不复制。
- 全局资源与插件私有存储不复制。
- 全局配置、适配器账号与收发名单不随聊天迁移改变。
- 按真实事件统计的实例消息、工具及模型总量不因复制增加。

长期记忆会覆盖目标聊天范围：保留来源、其他聊天流、全局和人物记忆，按内容哈希共享的向量与图片资产不重复生成。来源为空时会清空目标对应范围，执行前必须显式确认。

## 预览与冲突处理

在「数据管理 → 聊天迁移」选好来源和目标后预览。预览展示每类数据的变更数量，并把待处理项按配置、表达、黑话、命令分类列出。

::: fields
- **配置冲突** — 目标没有独立配置或仍用默认值时自动采用来源配置并在预览列出；定制配置的差异需要逐项选择。
- **其他冲突** — 按可读字段展示两侧取值，用按钮选择来源或目标。
- **未迁移记录** — 来源里已经处理过的记录仍逐项检查表达、黑话和命令冲突，不会自动跳过。
:::

所有待处理项都有明确决定后才允许提交。同一黑话已关联迁移双方时直接跳过，不产生冲突；不同记录即使黑话文字相同，仍按逐项冲突处理，采用来源时只解除旧目标关联，不影响其他聊天流。

执行前会重新核对数据和配置。预览之后数据或配置发生变化，需要重新预览，不能沿用旧结果。

## 执行与恢复

确认目标长期记忆将被覆盖后执行。任务在服务端后台继续，离开页面不取消；回到「迁移记录」可以重新打开进度。

跨数据库、配置和记忆的阶段记录用于失败恢复：主数据库提交前，恢复已改动的配置与记忆；提交后完成缓存刷新。进程异常退出后，在迁移记录里点「恢复迁移任务」，恢复结束再创建新预览。

重复迁移只追加新数据或新增贡献，普通记录按来源聊天流与来源记录 ID 去重，不会重复累加，也不会因循环迁移反复累加。

## 验证与排错

**验证**：迁移完成后在「聊天管理」打开目标聊天流，历史消息应与来源一致，消息仍显示原始发送者；再让麦麦在目标聊天里提一句来源聊过的事，长期记忆应能检索到。

- **预览不可用** — 来源和目标都要选中，且不能是同一个聊天流。
- **提示预览过期** — 预览到执行之间数据或配置有变化；重新预览再执行。
- **还有未处理项** — 所有冲突都要选完才能提交，检查是否有筛选项把未处理项藏起来了。
- **目标长期记忆被清空** — 来源对应的记忆范围为空时会清空目标范围；这是预览中的显式确认项，执行前先看清计数。
- **离开页面后任务消失** — 任务在服务端继续，回到「迁移记录」按状态查看，不需要重新执行。
- **恢复时提示存在后续修改** — 恢复不会静默覆盖新数据，双方保持暂停；按提示处理冲突后再恢复。
- **提示未声明的数据表** — 新增带聊天归属字段的数据表没有声明迁移规则，迁移会被阻止并显示表名，先补规则再迁移。
