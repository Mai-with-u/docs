# 聊天记录和统计

看看 MaiBot 有多活跃，都聊了什么！

## 聊天统计

### 📊 数据总览
打开"聊天统计"页面，能看到：
- **总消息数** - 机器人收到多少消息
- **回复数** - 机器人回复了多少条
- **在线时长** - 机器人运行了多久
- **平均响应** - 回复速度有多快

### 💰 费用统计
还能看到花钱的情况：
- **总花费** - 一共花了多少钱
- **每小时花费** - 平均每小时多少钱
- **Token 用量** - AI 处理了多少文字
- **各模型花费** - 不同 AI 模型分别花了多少

### 📈 趋势图表
直观的图表显示：
- **24 小时** - 最近一天的活动情况
- **7 天** - 最近一周的趋势
- **高峰时段** - 什么时候最活跃

## 详细统计页面

侧边栏「统计」入口（`/statistics`）提供可交互的原生详细统计页面，取代了传统的静态 HTML 报告（旧报告仍可通过访问 `maibot_statistics.html` 查看）。页面顶部可以切换时间范围：

- **全部时间 / 最近 30 天 / 最近 7 天 / 最近 3 天**
- **最近 24 小时 / 最近 3 小时 / 最近 1 小时 / 最近 15 分钟**

### 核心指标

- **在线时长** - 机器人累计运行时长
- **消息数 / 回复数** - 收到的消息与发出的回复数量
- **请求数 / Token 用量** - 模型调用次数与输入、输出 Token 总量
- **缓存命中** - 缓存命中与未命中 Token 数及命中率
- **费用** - 总花费、每百条消息成本、每小时成本等

### 多维分析

详细统计支持按以下维度展开分析：

- **模型** - 每个模型的请求数、Token、缓存命中率、费用和平均耗时
- **模块** - 按功能模块聚合的调用分布
- **请求类型** - 不同请求类型的成本占比
- **聊天流** - 各聊天流的消息量与成本
- **趋势** - 按时间序列展示成本、消息量等指标的变化
- **性能指标** - 每百条消息成本、每小时 Token 量等关键指标走势

## 表达方式

### 说话风格
MaiBot 会学习不同的表达方式：
- 正式/随意
- 活泼/沉稳
- 幽默/严肃
- 各种网络用语

### 黑话管理
机器人学到的网络用语：
- 新词热词
- 梗和段子
- 小圈子术语
- 可以手动确认或拒绝

### 表情包
收集的表情包：
- 使用频率统计
- 热门表情包
- 可以上传新的
- 禁用不合适的

表情包在 WebUI 中统一显示为四种状态：
- **认识**：有描述，但未注册、未封禁
- **不认识**：还没有描述，且未注册、未封禁
- **据为己用**：已经注册，可被 MaiBot 使用
- **丢弃**：已经封禁，不再使用

从 WebUI 手动上传的表情会直接标记为「据为己用」。上传时填写的标签列表会合并为表情描述；如果图片已存在于数据库，会复用原记录、更新描述、解除封禁并标记为已注册。删除未注册表情时会同步删除数据库记录和本地文件；删除已注册表情时会先从可用表情库卸载，再删除数据库记录和文件。

## 回复效果评估 {#reply-effect-evaluation}

回复效果评估用来衡量 MaiBot 的每一条回复"好不好"——是否回应了用户、回应得是否恰当。这是调优 Prompt 或对比不同模型表现的重要参考。

### 开启

在 `bot_config.toml` 的 `[debug]` 段开启：

::: code-group

```toml [TOML ~vscode-icons:file-type-toml~]
[debug]
enable_reply_effect_tracking = true
```

:::

开启后，WebUI 侧边栏"高级工具"分组下会出现 **回复效果** 页面（`/reply-effects`）。

### 评分语义（当前 v6）

评估标准经历多轮升级，当前实现为 **v6**：

- **回应度** — 衡量回复是否回应了用户，不再把"用户回应速度"作为证据，其余回应证据按原权重比例归一化
- **总分** — 缺少明确语义的原始总分已移除，只看各维度的证据
- **无关联信息** — 未发现与回复相关的信息时不再生成置信度，记录标记为"已完成 / 无信息"
- **不完整记录** — 未走完观察窗口（还在观察后续反馈）的记录标记为"不完整"，不参与评分与聚合统计
- **失败重试** — 评估过程中因 Prompt 截断等原因失败的记录，重启后会自动重试

### 查看与操作

- **评分分布** — 评分以逐条样本散点图展示，直观呈现零分堆积、离群值与模型组内波动
- **删除 / 清空评分** — 可以删除单条评分记录，或清空整个聊天 / 全局的评分数据
- **记录上限** — 每个聊天最多保留 `maisaka_reply_effect_limit` 条记录（默认 256），超出的旧记录自动清理

## 推理过程 Token 展示

**推理过程**页面（`/reasoning-process`）的日志列表与详情中，每条 LLM 请求现在会展示：

- **输入 Token** — 请求发送给模型的 Token 数
- **输出 Token** — 模型返回的 Token 数
- **总 Token** — 输入 + 输出的合计

方便直观评估一次回复的推理成本，尤其是高活跃群聊中的费用增长。

## 使用建议

### 日常查看
- 每天看看统计数据，了解活跃度
- 关注费用变化，避免超支
- 查看用户反馈，改进机器人

### 数据分析
- 分析高峰时段，合理安排维护
- 观察用户偏好，调整机器人性格
- 统计热门话题，增加相关内容

### 优化建议
- 响应太慢？检查配置
- 费用太高？换便宜模型
- 用户太少？增加推广

## 常见问题

**Q: 统计数据多久更新？**
A: 实时更新，随时能看到最新数据

**Q: 记录会保存多久？**
A: 默认长期保存，可以设置自动清理

**Q: 可以导出数据吗？**
A: 暂不支持导出功能，未来版本会添加

**Q: 如何降低使用费用？**
A: 选择便宜模型，减少不必要的调用，优化提示词

## 实用技巧

### 监控机器人健康
- 响应时间突然变长？可能有问题
- 费用异常增加？检查是否被攻击
- 活跃用户下降？看看是不是说错话了

### 改善用户体验
- 分析用户画像，个性化回复
- 统计热门话题，准备相关内容
- 记录用户反馈，持续改进

### 节省开支
- 选择性价比高的模型
- 设置合理的调用频率
- 避免重复调用浪费 Token
