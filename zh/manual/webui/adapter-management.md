# 适配器管理

适配器负责把 QQ、邮件、iMessage 等消息平台接入 MaiBot。WebUI 的适配器管理页（侧边栏「麦麦配置编辑」分组下的 **适配器设置**，`/adapter-management`）让你集中查看和管理所有已接入的适配器及其账号身份。

![适配器管理](/images/webui/adapter-management.webp)

## 查看已发现的账号

适配器连接后，会把它实际报告的平台账号身份上报给 MaiBot。适配器管理页会展示这些**已发现账号**：

- **账号身份** — 适配器实际报告的账号 ID、昵称等（1.2.0 起持久化保存，作为该适配器的稳定身份）
- **所属适配器** — 每个账号对应的适配器实例
- **在线状态** — 账号当前是否在线、适配器连接是否正常
- **身份来源** — 区分「适配器上报的身份」与「配置里的备用账号」，避免混淆

::: tip 与备用配置的区别
从 1.2.0 起，MaiBot 以适配器**实际报告的身份**为准。配置里手填的平台账号仅在没有适配器身份时作为备用值回退。两者都能在适配器管理页中区分查看。
:::

## 软禁用 / 恢复账号

对某个已发现账号，可以执行**软禁用**：

- **软禁用** — 账号不再接收入站消息，但适配器连接保持不断开，便于排查问题
- **恢复** — 取消软禁用，账号恢复正常接收入站消息

软禁用是 1.2.0 新增的运维手段，比直接停用整个适配器更精细——你可以只禁用出问题的账号，而不影响同一实例上的其他账号。

## 自动获取 ID

1.2.0 起适配器可以**自动获取并上报自己的 ID**，无需在配置里手动填写。适配器管理页会展示自动获取到的 ID 及身份信息，帮助确认每个适配器实例的身份是否被正确识别。

## 访问策略入口

适配器的**群聊 / 私聊访问策略**（谁可以被该适配器接入）在 WebUI 里有两个入口：

- **适配器管理页顶部的「麦麦默认策略」卡片** — 分别设置群聊与私聊在没有任何具体规则命中时的默认动作（放行 / 拒绝）
- **适配器插件配置页的「黑白名单规则」页签** — 只在 `plugin_type = adapter` 的插件上出现，按适配器实例配置具体的 `allow_ids` / `deny_ids`

「黑白名单规则」面板改为**编辑停止 2 秒后自动保存**，也可以点「保存」立即提交；页面会显示「未保存的更改 / 自动保存中 / 已保存 HH:MM:SS」等状态。

策略背后的配置文件是 `config/adapter_policy.toml`，详见 [接入平台](../adapters/index.md)。这里的规则属于 MaiBot 主程序侧。

从 1.3.0 起，适配器插件可以直接使用这套内置黑白名单；同时适配器管理页读写的是**运行时实际生效的那条规则**（多条规则命中时取最具体的一条），不会再把修改保存到被更高优先级规则遮蔽的条目上。

## 验证与排错

**验证**：接入一个适配器后，适配器管理页能看到对应账号且在线状态正常。

**看不到账号？**

- 确认适配器已连接并成功登录平台
- 适配器未上报身份时，页面会回退显示配置里的备用账号

**软禁用没生效？**

- 软禁用只影响入站消息，适配器连接保持不断开
- 确认操作的是目标账号，而不是同实例的其他账号
