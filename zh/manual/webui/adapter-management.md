# 适配器管理

适配器把 QQ、Telegram 等消息平台接进 MaiBot。侧边栏「配置管理 → 适配器设置」（`/adapter-management`）列出已安装的适配器，确认它们上报的平台账号，并把群聊 / 私聊的放行范围写进 `config/adapter_policy.toml`。

![适配器管理](/images/webui/adapter-management.webp)

## 适配器列表

页面按运行状态分组，组标题右侧是数量：

::: fields
- **运行中** — 适配器已加载并连上平台。
- **加载中 / 已离线** — 正在启动，或进程已经退出。
- **加载失败** — 展开看失败原因，可以直接更新版本或去插件市场换一个。
- **已禁用 / 未激活 / 运行时未启动** — 没有启用、没连上平台，或宿主还没拉起它。
:::

每行的开关控制适配器启停；行尾 `⋮` 里是「更新至 vX」和「卸载适配器」，内置适配器没有这一项。右上角「添加连接」只列插件市场里 `plugin_type = adapter`、与本机兼容、且不是本地来源的插件；独立的 NapCat 适配器也被排除。装好后回到列表配置，本机缺 Git 时对话框会直接提示。

## 平台账号

适配器连上平台后会上报自己实际持有的账号身份，页面存成**已发现账号**：

::: fields
- **账号** — 平台名加账号 ID，例如 `qq` 与 `2814567326`。
- **在线状态** — 最近一次上报时是否在线。
- **上报来源** — 最近一次是通过「就绪状态」还是「入站消息」上报，以及上报时间。
:::

顶部「平台账号」按钮打开账号面板：上半区是已发现账号，可以删掉单条记录（适配器再次上报时会重新发现）；「已排除账号」折叠区里点「恢复身份」把它放回来。

「备用平台账号」里手填的账号是兜底身份，只在适配器没有上报身份时使用，保存后写进 `bot_config.toml` 的 `[bot]`：

::: fields
- **`platform`** — 备用主平台，例如 `qq`。
- **`qq_account`** — 备用 QQ 账号 ID。
- **`platforms`** — 其他平台的备用账号，每条写成 `平台:账号`。
:::

## 黑白名单设置

页面顶部那张卡设全局兜底规则：群聊、私聊各一个开关，「接收」或「不接收」。没有命中任何具体规则的聊天都走这里，对应 `config/adapter_policy.toml` 的 `[defaults.group]` 和 `[defaults.private]`。

## 单个适配器的规则

选中适配器后，「黑白名单规则」只在 `plugin_type = adapter` 的插件配置页出现；适配器没连上平台时，这一栏提示先去补连接配置。

规则分群聊与私聊两块：

::: fields
- **当前账号 ID** — 规则按账号 ID 存。换号登录后旧账号的条目留在配置里但不再生效，页面会提示当前账号还没有专属规则。
- **默认规则** — 「接收所有消息」「默认不接收消息」，或「与全局设置一致」。后者表示这一层不管，继续用顶部的全局设置。
- **接收名单 / 拒收名单** — 默认接收时只需要填拒收名单，默认不接收时只需要填接收名单；两个名单都支持 `*` 匹配全部。
:::

名单里每条 ID 右侧有开关：关掉只让它暂不参与匹配，记录还在，重新打开就继续用。拒收先于接收判定，同一个 ID 同时写进两个名单会被后端拒绝保存。

名单里的 ID 必须和适配器上报的群号 / 用户 ID 完全一致。群号列表会带出群头像和群名，用来核对填的是不是同一个群。

编辑停止 2 秒后自动保存，工具栏显示「已保存 HH:MM:SS」或「未保存的更改」。适配器断开后无法确定规则归属，草稿不会提交。

## 策略分组

同一适配器的规则可以存成多套分组，按场景切换：

::: fields
- **切换分组** — 立即保存并生效，当前草稿先写回原分组。
- **新建分组** — 继承全局设置、名单为空，名称不能与已有分组重名；创建后要自己切过去。
- **复制当前组** — 复制当前分组的全部规则，创建后仍停在原来的分组。
- **管理分组** — 删除分组。当前生效的那组不能删，先切走再删。
:::

## 生效范围

保存后文件监听器重新读取 `config/adapter_policy.toml`，被新规则拦下的运行中会话立刻停止并注销，不需要重启宿主。

内置聊天室、WebUI 聊天室和本地控制台不走适配器名单，任何规则都拦不到它们。

条目之间的优先级、身份的六个字段和 `disabled` 的写法见[访问策略与账户路由](/develop/adapters/policy)。

## 验证与排错

**验证**：在放行的测试群发一条消息，麦麦正常回复；把该群填进拒收名单后，同一条消息不再触发回复。

- **列表是空的** — 走「添加连接」安装适配器；装好却没显示时确认它的 `plugin_type` 是 `adapter`。
- **找不到「黑白名单规则」** — 这一栏只在 `/adapter-management` 页打开适配器时出现，插件详情页里没有。
- **规则栏提示先连上平台** — 适配器还没上报账号身份，先修好连接配置并启用。
- **配了拒收却还在回复** — 核对 ID 与适配器上报的是否完全一致：匹配是精确相等或 `*`，不做前缀匹配；再确认这条 ID 的开关没被关掉。
- **换号后旧规则失效** — 正常现象：规则按账号 ID 存，切到新账号要重新配置。
