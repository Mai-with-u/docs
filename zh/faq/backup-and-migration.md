# 数据与迁移

这页解决数据搬迁问题：备份哪些目录、怎么导出和恢复、换机器后怎么重新登记 Bot。

## 迁移或重装前要备份什么？

整目录复制这三项：

- **`config/`** — 所有配置：`bot_config.toml`、`model_config.toml`、`adapter_policy.toml`、`builtin_plugins/`。
- **`host/`** — 宿主配置 `config.toml`、Bot 登记表 `registry.sqlite3`、共享模型目录 `model_catalog.toml`、WebUI 凭据 `webui.json`。
- **`data/`** — 数据库、长期记忆、文件、表情包缓存。
- **`plugins/`** — 已安装的第三方插件和它们目录内的配置与数据。

`host/webui.json` 丢了要重新设置 WebUI 密码；`host/registry.sqlite3` 丢了，工作区里的 Bot 要从目录重新登记。适配器或一键包把配置存在 MaiBot 目录外的，也要单独备份。

## 用 WebUI 数据管理页导出

WebUI 侧边栏「高级工具 → 数据管理」（`/data-transfer`）。导出是异步任务，页面显示进度，完成后直接在浏览器下载 zip。`config` + `data` 固定勾选，另外两项按需：

**`plugins`** — 已安装插件及其目录内的配置和数据。

**`logs`** — 运行日志。

压缩包里有 `manifest.json`，记录导出时间、MaiBot 版本和各部分文件统计；导入时后端按 `config` / `data` / `plugins` / `logs` 四个分块还原。

### 导出历史与 24 小时保留

导出卡片下面是导出历史，每条显示文件名、体积、完成时间和保留截止时间。

- 压缩包只存在服务器临时目录，**保留 24 小时**；每点一次下载重新计时。
- 保留期内刷新页面或重启 MaiBot 都能重新下载，历史记录持久化在临时目录。
- 超期后显示「文件已过期或已删除」，下载按钮置灰。
- 导出中或下载中被删除会返回 409，等它结束再删。

### 不会被打包的内容

`data/.a_memorix_runtime_writer.lock` 等运行锁，以及 `data/prompt_imgs/` 推理预览图片目录。后者要手动复制。取消导出会连已生成的压缩包一起删除。

## 怎样迁移到另一台设备？

1. 停止宿主、适配器和启动器。
2. 备份整个工作区目录，记下当前版本。
3. 目标机器上装好同版本或更新版本的 MaiBot 与运行环境。
4. 把 `config`、`host`、`data`、`plugins`、`bots` 放回工作区。
5. 检查配置里的绝对路径、端口、文件权限和网络地址。
6. 启动后看配置升级、数据库迁移和插件加载日志。

确认新位置正常后再删旧副本。用 WebUI 导出的 zip 恢复时，后端会校验 manifest，并在解包前拒绝符号链接、`..` 路径穿越和白名单外的顶层目录。

## `maibot host adopt` 和直接复制目录有什么区别？

`adopt` 把一个已有实例登记进工作区，不转换数据格式：

- **`--mode register`** — 只登记路径，目录原地保留，零成本。
- **`--mode move`** — 在同一文件系统内把目录重命名到 `bots/<id>/`，跨盘直接拒绝。步骤记在 `host/migrations/<bot_id>.json`，中断后重跑同一条命令即可续上。

手动复制目录不会写登记表，工作区不会认识这个 Bot。移植旧实例请用 `adopt`，见[多实例](../manual/multi-bot-host.md#迁入旧实例)。

## 恢复备份后启动不了怎么办？

按顺序查：源版本与目标版本是否兼容、配置是否需要升级、数据库迁移是否失败、插件是否支持当前版本、文件权限和绝对路径是否还有效。

在没有额外备份的情况下，不要删数据库，也不要覆盖原始备份。

## 本地模型提示禁止访问非公网地址怎么办？

这是 WebUI 的出站 URL 安全校验（`[webui].enforce_public_outbound_url`，默认 `true`）。确认目标确实是可信的本地或内网服务后，可以在 WebUI 的公共设置里关掉它。

关掉后 WebUI 允许访问内网地址，同时也削弱了防服务端请求伪造的保护。模型服务跑在 Docker 或另一台设备上时，请改填 MaiBot 所在环境能访问到的地址。

## 从只读备份里恢复会不会把宿主配置搞乱？

不会。导入用户态备份时只还原 Bot 自身的业务配置：`host/config.toml` 的监听地址、凭据和保留策略不会从备份包覆盖，公共模型目录也是合并而不是替换。这些由宿主统一维护，不随单个 Bot 迁移。
